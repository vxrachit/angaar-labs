# Git Workflow

The team follows a feature-branch workflow.

1. Checkout latest `main`.
2. Pull latest changes.
3. Create a feature branch.
4. Implement the feature.
5. Test locally.
6. Commit meaningful changes.
7. Push the branch.
8. Create a Pull Request.
9. Review the changes.
10. Merge into `main`.

---

# Commit Convention

Examples:

- `feat(hero): build cinematic hero section`
- `feat(hero): add interactive 3d scene`
- `feat(scroll): add shared scroll utility`
- `feat(work): build portfolio section`
- `fix(ui): improve responsiveness animations and layout`
- `docs: document frontend architecture`
- `docs: document AI development prompts`

---

# Contribution Principle

Every member should contribute through their own GitHub account.

Commits should represent meaningful work rather than one large final commit.

Each team member should understand the code they contributed because the project includes a viva component.
